# 臨時休市查價備援

狀態：修復及94項隔離回歸通過，尚未發布。來源任務 `01a157c0-b093-70cf-8e24-55c477db90d7`；2026/10/23 使用者明確採用「行事曆為主，舊判定作備援」。本案不更動策略、T4/S65、市場7或原始資料。

## 原因與既有行為

App 使用 [TWSE OpenAPI 年度行事曆](https://openapi.twse.com.tw/v1/holidaySchedule/holidaySchedule)，快取24小時、失敗間隔1小時。2026/10/23直接取得27筆，10月只有9、10、25、26日，沒有23日。它也包含開始／最後交易日，程式已有區分，不能把每筆當休市。[官方資料集](https://data.gov.tw/dataset/11761)標示每年更新，不能當臨時休市即時來源。今天臺北市停班與[TWSE天然災害休市規定](https://www.twse.com.tw/zh/about/suspended_faq.html)相符；沒有新增政府公告爬蟲。

`TWSETradingCalendar.status` 將年度表未列出的平日視為交易日。現行 Yahoo 個股／大盤解析原本將「格式完整、日期較舊」與格式錯誤合在一起；失敗不記錄成功查價時間，回前景與盤中定時流程便再次查詢。這次不是單純快取過期，強制刷新同一年度來源仍缺該日。

封存 `technical_20260509-122804.swift` 與 `technical_20260509-114510.swift` 都有雙向判定：09:05後回覆不是今日時設 `isOffDay = true`，今日行情則進入 `else` 設為 `false`（`yahooQuote` 951／955行；另一個 `yahooRequest` 為844／848行）。`runRequest` 於205行以 `allGroup.notify` 等待整輪完成，才記錄最終旗標、決定是否安排下一次查價；148行跨日清除，重啟後旗標不保留。沒有額外連續次數門檻。先前只引用設為true的分支，並稱「沒有等整輪」的說明不完整，於本節更正。

完整控制流另有911行的請求前短路，網路回覆則是非同步；`serialQueue` 只依序啟動工作，不等待網路回覆。這份快照的回呼直接雙向寫入同一旗標，未另保存「本輪曾有今日行情」的累積證據，因此靜態上尚不能保證回覆順序無關；這不是已證實使用者曾遇到誤判。本次依使用者確認的整輪原則，統一在所有回覆彙總後判定，任何有效今日行情都否決休市備援，後續舊行情不得覆蓋它。

## 本次契約

- 行事曆明列休市時仍先略過；備援不覆寫官方行事曆或應完成的正式交易日。
- 09:05後，完整一輪所選股票全部取得有效、早於今天的行情，且有效加權指數日期等於日曆所推的上一交易日，才設定當日自動查價暫停旗標。沒有選股、少一筆、任一當日行情、來源失敗、資料無效或取消都不能形成此旗標。今日行情優先與回覆順序無關，「舊→今日」及「今日→舊」皆不能判休市；HTTP失敗不當成無當日交易。
- 只接受有效HTTP、日期及完整合理OHLC；個股另須合法成交量。舊行情不寫成今日價格、不建立假Trade／MarketDay、不使T/S失效。
- 旗標限Yahoo自動查價，不代替TWSE月份完成證據，不阻止既有正式補價／重算。年度行事曆對臨時休市的缺項仍可能使正式歷史來源需要確認，不以推定旗標宣告完整。
- 日期旗標成功原子保存後才啟用，重新啟動仍可讀取；下一個臺北日期自然不適用。手動全股群／個股更新均先清除再查，正常交易可恢復；無法清除或保存時記錄明確錯誤。
- Yahoo全市場若同時持續提供前日有效頁面，仍可能觸發備援，這是原判定的資料限制，不宣稱官方確認。手動更新是重新確認入口。

## 驗證與交付

使用現有專用Contract Tests Simulator及假資料／HTTP回覆，不操作實體裝置、正常Simulator或正式資料庫。測試涵蓋完整更新入口第一輪、三次回前景零重查、日曆與計算資料不變、重新建立物件後持續、手動重新查得當日行情、開盤緩衝／跨日、個股無成交而大盤正常、HTTP／格式／連線失敗、取消及旗標保存失敗。另以兩檔股票驗證「舊→今日」與「今日→舊」回覆順序，兩種情況均完成全部查詢、不建立休市旗標。既有行情、前景更新及日曆測試一併回歸。94個不同案例的最新結果全部通過；核心整合驗證第一輪2個Yahoo請求、三次再更新及重新建立物件後零請求，手動重新確認可恢復當日行情。既有一項TWSE接算測試的假回覆只有7欄，與未修改的正式9欄解析器不符；補齊假回覆後原六項斷言全過，未放寬產品或測試條件。
