# 價格路徑狀態持久化計畫

## 目標與邊界

本計畫把 App 已顯示的 20 日價格路徑圖示改為逐筆 `Trade` 持久狀態，讓 List、Trade 與技術檢視在 App 重啟或捲動畫面時直接讀取結果，不再為顯示而重播整段歷史。狀態只使用當日及以前的正式收盤價；Yahoo 同日價格只覆寫當日試算，不能把查詢次數當成新交易日。它是可在當日決定的滾動狀態，不是[未來價格路徑研究](未來價格路徑與技術數值組合研究計畫.md#未來價格路徑標籤)使用後續 20 日價格才建立的結果標籤。

價格路徑是行情描述，不是 Grade，也不直接增加或扣除 H買、L買、賣出或加碼分數。`RP-H01／H02／H04／H05／S01` 的 Sample A 反證只否定相應候選，不否定圖示與前後期切割作為 UI 和研究資料。若未來要把任一階段納入規則，仍須另立單一變因候選並完整重播。

正式導入依[版本與資料重算](版本與資料重算.md)將技術資料版本由 `T2` 推進為 `T3`，模擬資料規則維持 `S39`。PP-T3-08 已發布 T3 App，PP-T3-09 已完成集中資料池、A～E 分片、Baseline v21 與 DecisionBase v7 更新。

## 波動門檻

以最近最多 60 個相鄰正式收盤價的對數報酬計算樣本標準差，至少需要 40 筆報酬。20 日波動門檻為：

```text
b = clamp(sampleSigma(logReturn) × sqrt(20), 0.05, 0.15)
```

每個新區段建立時凍結當時的 `b`，區段內不因後續波動重新縮放。盤整超過正負 `b` 才建立探頂或探底；趨勢區段連續 20 個正式交易日沒有新極值時回到盤整。無效價格或日期不遞增會中斷序列，重新累積暖機資料。

## 前後期切割

四組狀態共用「相對於凍結門檻 `b` 的價格進度」方法，但主趨勢與轉折階段使用不同切點。

| 狀態 | 標準化進度 | 前期 | 後期 |
|---|---|---:|---:|
| 探頂 | `(runningHigh / anchorClose - 1) / b` | `1.0 <= p < 1.5` | `p >= 1.5` |
| 拉回 | `((runningHigh - close) / runningHigh) / b` | `0.5 <= p < 0.75` | `p >= 0.75` |
| 探底 | `((anchorClose - runningLow) / anchorClose) / b` | `1.0 <= p < 1.5` | `p >= 1.5` |
| 反彈 | `((close - runningLow) / runningLow) / b` | `0.5 <= p < 0.75` | `p >= 0.75` |

拉回或反彈達 `1.0b` 是轉入相反主趨勢的門檻。為維持「先轉折、再成為新趨勢」的連續性，狀態機每個交易日最多前進一個階段：若價格由探頂當日直接跨過 `1.0b` 回落，該日先記為拉回後期；下一個有效交易日仍符合時才成為探底。反彈轉探頂亦同。新高會由拉回回到探頂，新低會由反彈回到探底，舊日期不回改。

`1.5b` 曾用於 `RP-H05` 的 H買扣分候選並在 Sample A 退步；本計畫只把它固定為探頂／探底的顯示分段，不將該候選改寫成正式規則。`0.75b` 是拉回／反彈既有 `0.5b` 起轉與 `1.0b` 換向門檻的中點，同樣只描述階段進度。
