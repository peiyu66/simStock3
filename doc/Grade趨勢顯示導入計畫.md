# Grade 趨勢顯示導入計畫

> `±0.3` 先期預警、確認後退回抑制、S22 SwiftData 階段與後續資料遷移，改由[Grade 趨勢預警狀態持久化計畫](Grade趨勢預警狀態持久化計畫.md)接續管理；現行探頂／拉回、探底／反彈圖示見[選股評等的 Grade 趨勢圖示](選股評等.md#grade-趨勢圖示)。本檔只保留原 Grade 趨勢圖示導入歷史。

## 結論與目的

本案將適配趨勢正式保存於每個交易日的 `Trade`，並在現有 Grade 圖示旁顯示改善或惡化方向。這是狀態提示，不是買賣訊號；本案不修改 Grade、買賣分數、交易門檻或 Baseline。

第一版沿用 [適配趨勢研究與導入計畫](適配趨勢研究與導入計畫.md) 已確認的 20／125 EMA 與 FT3 噪音帶 `±0.611888`：

| 狀態 | 顯示規則 |
|---|---|
| 改善 | 觀察數至少 125，且 `simFitTrend > 0.611888`，顯示向上圖示 |
| 惡化 | 觀察數至少 125，且 `simFitTrend < -0.611888`，顯示向下圖示 |
| 穩定或資料不足 | 不顯示方向圖示，但保留等寬位置 |

門檻只用來排除短期噪音，不代表上漲、下跌、正確率或賣出機率。Grade 本身的圖示與顏色維持不變，趨勢圖示另以方向、顏色及無障礙標籤表達狀態。

## 範圍與限制

- 趨勢屬於 `simUpdate` 狀態，不寫入 `tUpdate`。
- UI 可以讀取趨勢；正式交易規則在另案通過回測並採用前不得讀取。
- 不加入背景遙測，不自動上傳使用者資料。
- 不保存 `roiTrend`、`daysTrend` 或研究 DecisionBase 的事件明細。
- 本案需要推進 S 並重播模擬，但不推進 T，也不因純顯示功能重建交易 Baseline。
- 實作開始時先確認當前版本；依目前狀態預計由 `T2/S19` 推進至 `T2/S20`。

## 正式資料設計

每筆合格交易日保存最小狀態：

| 欄位 | 用途 |
|---|---|
| `simFitFast: Double?` | 20 日效率 EMA |
| `simFitSlow: Double?` | 125 日效率 EMA |
| `simFitTrend: Double?` | `simFitFast - simFitSlow`，供 UI 與離線匯出 |
| `simFitObservationCount: Int` | 暖機與顯示資格 |

舊資料欄位先為 `nil`；不得用 `0` 代表尚未計算。非有限值不得寫入或推進觀察數。`simFitTrend` 雖可由 fast／slow 推導，仍正式保存，讓日後校正可以直接匯出，同時用 fast／slow 核對資料正確性。

每日時序固定如下：

1. 當日決策只能使用前一個合格交易日結束後的狀態。
2. 當日 `simUpdate` 完成後，以當日 Grade 背後的連續效率分數更新 EMA。
3. 將更新後狀態寫入當日 `Trade`，供當日歷史顯示與下一交易日使用。

## UI 規格

- Grade 圖示之後增加固定寬度的趨勢位置。
- 改善使用向上方向圖示；惡化使用向下方向圖示。
- 穩定、暖機不足、資料不存在或數值無效時不畫圖示，但保留占位。
- List、橫式側欄與 Page 使用相同欄位順序、尺寸與判斷函式。
- 趨勢圖示不可遮蓋或改寫 Grade 顏色，並提供「適配趨勢改善／惡化」無障礙標籤。
- 第一版不顯示數值、百分比或「穩定」圖示，避免把研究尺度誤讀為預測。

實作時再依既有 UI 視覺語言選定 SF Symbol 與顏色；不為圖示另建使用者設定。

## 校正資料來源

日後校正從正式資料庫的原始趨勢欄位產生離線資料，不以研究旁錄作為長期唯一來源。校正流程另案執行：

1. 使用者或開發者明確啟動匯出，不在背景蒐集。
2. 只匯出股票識別、交易日、fast、slow、trend、觀察數及 T/S／演算法版本。
3. 排除本金、持股、損益金額、手動反轉、手動加碼及其他個人操作。
4. 優先使用相同版本的受控重播資料計算新門檻，避免把不同版本或人工操作混入同一校正。
5. 校正結果先形成版本化報告；經確認後才修改顯示門檻，不自動漂移。

只調整顯示門檻、不改 EMA 或原始趨勢值時，不需推進 S 或重播；若改變 EMA 週期、效率公式或狀態更新方式，必須推進 S 並完整重播。

## 執行分段

完整導入預期超過 15 分鐘，不應一次無限擴張。建議依下列三段個別核准：

1. **資料段：GT1～GT2**：完成資料模型與寫入，解鎖「結果無副作用」判定。
2. **遷移段：GT3**：在資料段通過後才重播正式資料，解鎖真實裝置顯示資料。
3. **顯示段：GT4～GT5**：完成 UI 與驗證；是否 commit、安裝或 push 依使用者當次指示。

任一段發現會改變交易結果、破壞人工操作或需要擴大資料研究時，先保存成果並停止討論，不自行增加新前置專案。

## 完成定義

- 合格歷史交易日具有可重現的趨勢原始值。
- Grade 旁只在跨越門檻時顯示正確方向，其他狀態保持對齊。
- App 的 Grade、買賣規則、交易門檻與 Baseline 沒有變更。
- 資料遷移保留有效人工反轉與加碼，並有明確結果報告。
- 門檻來源、版本與未來離線校正方式可以追溯。
