# TWSE 歷史資料下載標準

## 目的與適用範圍

本文件公開說明 simStock3 使用 TWSE 月份查詢端點進行歷史補齊時的安全原則，包括個股 `/exchangeReport/STOCK_DAY`，以及研究資料池使用的 `/indicesReport/MI_5MINS_HIST` 與 `/exchangeReport/FMTQIK`。日常少量更新仍由正式 App 或對應資料池流程管理；大量歷史補齊必須使用受控、可停止且可續跑的流程，不得直接建立未限速的快速迴圈。

TWSE 官方目前沒有為這些網頁查詢端點公布固定請求間隔。本專案自行採取保守的請求間隔、有限重試與錯誤退避；程式中的現行參數只是專案工程值，不是 TWSE 官方容許量、服務保證或可供提高頻率的依據。

## 請求與服務界線

1. 所有月份請求必須單線依序執行，不得並行。
2. 使用程式既定的保守間隔；不得為縮短作業時間而自行提高頻率、增加平行數或移除等待。
3. 大量補齊先做限定範圍的試跑，確認回應格式與服務狀態正常後才繼續；試跑不是探索服務容許上限。
4. 任一請求出現逾時、非 JSON、HTTP `429`、HTTP `5xx` 或其他伺服器異常，立即降低後續請求頻率並依有限退避重試；異常持續時停止整批下載。
5. 收到明確警告、停止通知或可合理判定是針對自動存取的封鎖時，立即停止該資料來源，不更換 IP、偽裝請求或以其他方法規避限制。
6. 能由具明確開放授權的來源取得相同資料時，優先使用該來源；不得把網站可存取直接解讀為已取得自動下載授權。

## 失敗與退避

1. 失敗月份不得標記為完成，也不得因此執行後續 `tUpdate` 或 `simUpdate`。
2. 同一月份只允許有限次數且逐次延長等待的重試，不得無限重送。
3. 同一月份用完重試次數，或連續多個月份失敗時，停止整批下載並保存進度，不再向 TWSE 持續送出請求。
4. 下次重啟只請求尚未完成的月份；已成功月份不得重複下載。

## 資料安全與完成條件

1. 歷史補齊只寫入可續跑的工作副本；既有來源資料池與 A～E Baseline 保持不變。
2. 每次請求至少記錄股票或來源、月份、使用間隔、成功或失敗，以及可取得的錯誤類型。
3. 全批成功並通過原始資料品質檢查後，才可標記完整原始資料；只有任務另含技術值時才接續 `tUpdate` 或市場技術值計算。
4. 完成檢查至少包含預期來源／股票數、起訖日期、正值且有限的價格、來源間共同欄位一致，以及任務所需技術值沒有 `NaN` 或 `Inf`。
5. 降速、停止或續跑都屬預期控制流程，不應被誤報為資料搬移或模擬規則失敗。

## 維護界線

- 公開文件只保留行為原則、資料安全與停止界線，不列出用來執行批次工作的精確間隔、試跑上限或重試序列。
- 精確參數由現行程式與本機操作紀錄維護；修改參數仍須檢查服務條款、實際錯誤訊號、資料完整性與專案授權，不得只因先前曾成功就提高頻率。
- 若實際行為與本文件的保守原則不一致，應先停止批次並修正流程，不得以隱藏文件代替降低風險。
