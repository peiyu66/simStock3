# TWSE 歷史資料下載標準

## 目的與適用範圍

本文件規範 simStock3 使用 TWSE 個股月份查詢端點 `/exchangeReport/STOCK_DAY` 進行歷史價格補齊時的節流、失敗處理、續跑及發布方式。日常少量更新仍由正式 App 流程管理；大量歷史補齊不得直接照搬未受控的快速迴圈。

TWSE 官方目前沒有為此網頁查詢端點公布固定請求間隔。以下秒數是本專案依現行 App 與實測建立的工程標準，不是 TWSE 官方保證。

## 請求節流

1. 所有月份請求必須單線依序執行，不得並行。
2. 新批次先以現行日常更新相同的 `1.5 秒`間隔做限定試跑。
3. 限定試跑以一檔股票或最多 18 個連續月份為界；全部成功後，才可沿用 `1.5 秒`完成同一批工作。
4. 任一請求出現逾時、非 JSON、HTTP `429`、HTTP `5xx` 或其他伺服器異常，該批後續立即降為每次 `5 秒`。
5. 間隔是前一個請求完成後，到下一個請求開始前的等待時間；網路回應時間另計。

## 失敗與退避

1. 失敗月份不得標記為完成，也不得因此執行後續 `tUpdate` 或 `simUpdate`。
2. 同一月份重試前依序等待 `15 秒`、`30 秒`、`60 秒`。
3. 同一月份三次仍失敗，或連續三個月份失敗，停止整批下載並保存進度，不再向 TWSE 持續送出請求。
4. 下次重啟只請求尚未完成的月份；已成功月份不得重複下載。

## 資料安全與完成條件

1. 歷史補齊只寫入可續跑的工作副本；來源資料池與既有 A／B Baseline 保持不變。
2. 每次請求至少記錄股票、月份、使用間隔、成功或失敗，以及可取得的錯誤類型。
3. 全批成功後才執行完整 `tUpdate` 與資料品質檢查；在此之前不得發布為完整資料池。
4. 完成檢查至少包含預期股票數、起訖日期、正值且有限的價格，以及關鍵技術值沒有 `NaN` 或 `Inf`。
5. 降速、停止或續跑都屬預期控制流程，不應被誤報為資料搬移或模擬規則失敗。

## 目前採用值

| 使用情境 | 間隔 | 說明 |
|---|---:|---|
| 日常少量更新 | `1.5 秒` | 現行正式 App 經驗值 |
| 歷史批次限定試跑 | `1.5 秒` | 單線，最多一檔或 18 個月份 |
| 歷史批次降速 | `5 秒` | 發生任何伺服器或格式異常後採用 |
