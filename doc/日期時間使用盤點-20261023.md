## 結論與證據界線

**目前不是全部沿用 `twDateTime`，也不能說沒有各自計算。** 多數窗口、資料重算及日期顯示使用它或它的 `calendar`；仍有裝置日曆、另一套台北日曆、分散的交易時段、年月日解析及天數換算。

最優先的是 `Trade` 的每日邊界：TWSE 月行情的正式匯入在按日查重時，會使用 `Calendar.current`，而解析日期與保存收盤時間使用台北時區。這不是單純風格問題。

## `twDateTime` 目前提供什麼

定義於 [utility.swift:606](../simStock3/utility.swift#L606)。類別宣告為 `public`，但其 `static` 成員沒有另外宣告 `public`；目前是 App 模組內共用能力。

| 能力 | 實作與範圍 |
| --- | --- |
| 日曆 | `calendar`：Gregorian、`zh_Hant_TW`、`Asia/Taipei`（608–612）。呼叫端直接使用此日曆的加年／月／日與比較，仍算沿用共用時區。 |
| 固定時刻 | `timeAtDate`、`time0900`、`time1330`（623、637、646）；以台北日曆組合時分秒。 |
| 日／月邊界 | `startOfDay`、`endOfDay`、`isDateInToday`、`startOfMonth`、`endOfMonth`（655–690）。 |
| 日期位移 | `yesterday`、`back10Days`（692、700）；其他位移由呼叫端透過 `twDateTime.calendar` 執行。 |
| 字串 | `formatter`、`dateFromString`、`stringFromDate`（615、708、716）；formatter 固定 locale／timeZone，未顯式指定 calendar，也沒有共用嚴格回轉驗證介面。 |
| 盤中 | `inMarketingTime`（721）：09:00 含起點、13:30 不含終點，可有 delay；不負責判斷交易日／休市日。`forToday` 另外讀取真實現在。 |

共用類別本身也有待整理的邊界：

- `endOfDay` 為 23:59:59，不是下一日的排他上界。探針確認「今日 23:59:59.500」會被 `isDateInToday` 判為 false；本輪未證明這會造成現行盤中流程的錯誤。
- `endOfMonth` 回傳月底最後一日 **00:00**。探針確認 2024 年 2 月得到 `2024/02/29 00:00:00`。全產品搜尋只有定義、沒有呼叫，故不是已發生的月底缺資料問題。
- `isDateInToday` 沒有 `asOf` 參數，內部兩個邊界分別取得現在；跨午夜的一致性與可注入時鐘能力不足。未實測跨午夜競態。

### B2．共用時區，但時段／休市運算分散

- [TWSETradingCalendar.swift:285](../simStock3/TWSETradingCalendar.swift#L285) 另建 Gregorian／Asia/Taipei／zh_Hant_TW 日曆，設定目前與 `twDateTime.calendar` 相同。不是 `Calendar.current` 錯誤，但存在雙份來源。
- 該服務在 160–230 行自行處理星期、休市／補交易日、15:35 發布門檻、逐日往回找最近已完成交易日；這是**有來源資料的交易日政策**，不能由 `twDateTime` 的「09:00～13:30」取代。快照年份不符／資料不足時可能回傳 unknown／nil，包含跨年往前查詢；此為保守行為，尚未做跨年整合驗證。
- [YahooTradingDayFallback.swift:15](../simStock3/YahooTradingDayFallback.swift#L15) 使用上述第二套日曆，另定 09:05 寬限時間；這是觀測性暫停，並非正式休市證明。
- [IntradayScenarioPolicy.swift:11](../simStock3/IntradayScenarioPolicy.swift#L11) 自行以時×60＋分判定 09:00～13:30；[simObject.swift:27](../simStock3/simObject.swift#L27) 的 `DailyPriceUpdatePolicy` 也自行定同一組時分。現行呼叫端（819、836）傳入台北日曆；沒有查到此處正在用裝置日曆。
- [uiObject.swift:1176](../simStock3/uiObject.swift#L1176) 自行指定 15:35 並排定任務；TWSETradingCalendar 196–203 也定義 15:35。`technical.swift:1221` 另保留開盤前／收盤後兩分鐘門檻。這些延遲有不同用途，應統一基礎時刻而保留各政策，不直接全部改成同一個時間。

### B3．月份、解析與設定 UI

- **月份尾界線：**[HistoryCompletion.swift:59](../simStock3/HistoryCompletion.swift#L59)、113 及 [technical.swift:3013](../simStock3/technical.swift#L3013) 用共用日曆找次月，再各自減一秒。這些是涵蓋證據的含尾界線，現行原始日資料為日首／13:30，尚未發現因此漏掉現有樣本；若一般化到小數秒，仍有最後一秒缺口。不能直接用目前 `endOfMonth` 替換。
- **實際現在：**月回應在 technical 3015 用 `Date()` 判定請求月份是否已完結；上層更新規劃則接受 `asOf`／clock。長時間下載跨月時，回應確認時間和規劃時間可能不同，應明定語意，尚未實測跨月下載。
- **民國年：**TWSEMonthlyResponse 48–55、MarketData 560–564 各自拆字串並加 1911；前者有年月日數值限制及完整日期回轉比對，後者只有 parse 與預期月份比對。TWSETradingCalendar 296–307 又自行組民國鍵、取前三碼加 1911。可共用嚴格的民國日期介面，但不是已證明目前閏日解析錯誤。
- **上市日：**[StockCatalog.swift:124](../simStock3/StockCatalog.swift#L124) 自建 `DateFormatter`，已指定共用 calendar／timeZone、8 碼檢查與 `isLenient=false`。它是來源專用嚴格 parser，不是獨立時區錯誤；適合在共用嚴格 parser 有同等能力後收斂。
- **DatePicker：**[viewPage.swift:778](../simStock3/viewPage.swift#L778)、[viewList.swift:2927](../simStock3/viewList.swift#L2927) 的可選範圍使用台北日曆減 15／1 年，但元件只設 locale，沒有設定 calendar／timeZone；全產品未找到提供這兩項的上層 environment。可能把 UI 選擇日期與計算日界線分開，且上下限各自呼叫 `Date()`。這是程式缺口，尚未在不同時區或曆法的 UI 驗證。

### B4．日數、年化及季節規則

- [technical.swift:3759](../simStock3/technical.swift#L3759) 以 `round((trade.date-prev.date)/86400)` 累計持股／輪次日數，會寫入模擬結果。時間來源為 B1 的 `Trade.date`，需優先整理來源；不能只因看到 86400 就改成「交易日筆數」。日數是日曆經過日數，週末仍計入。
- [dataModel.swift:428](../simStock3/dataModel.swift#L428)、1394 將台北窗口日期差除以 `86400×365`，至少一年，供[報酬率／年數](報酬率.md#年數)使用。這是既有年化口徑；「往前一個日曆年」與「用 365 日換算年化分母」不是同一件事。可抽共用日數與年化計算，不能順手改成完整日曆年數或改用 366 作分母。
- [technical.swift:3983](../simStock3/technical.swift#L3983) 將台北日期格式化成固定四碼 `MMdd`，以字串比較 H-C01～H-C04 的春季／夏季區間。它是各規則的日期判斷，不是只做 UI 格式化；目前都是同年內區間，固定補零字串具可比較性。未看到跨年區間，不能宣稱現有比較已錯；若抽共用 month/day 比較，需保留全部端點及閏日既有行為。
