# 大盤歷史資料與市場技術值前置計畫

## 計畫定位

- 計畫代號：`MKT-D01`。
- 第一階段建立的「非正式大盤」比照現有 50 檔集中資料池，是完整保存 TAIEX 真實 OHLC 與 `FMTQIK` 集中市場成交資訊的本機開發、回測研究資料，不是使用者 App 的正式資料庫。
- 非正式大盤可重複供研究、候選與 Baseline 更新使用；已驗收的歷史區段不隨每次重播重新下載，只在資料截止日延長時增量補齊。
- 若日後有大盤規則正式採用，另立 App 導入任務：新增正式市場資料模型、下載、技術重算、版本與遷移流程，由每位使用者的 App 建立並維護自己的正式大盤資料庫。不得直接把本機研究資料池稱為 App 已完成的市場資料。
- 研究資料與正式 App 資料在重疊日期必須能逐日對照來源欄位及適用技術值；對照通過只證明實作一致，不代表兩者是同一份資料庫。
- 研究資料池不以 App 的儲存空間、記憶體或 schema 簡潔度刪減來源欄位與現行可計算統計；正式 App 日後只挑已採用規則需要的子集。
- 本計畫先證明資料與技術值可用，不承諾一定發現有效交易規則。現行「大盤只作報告背景、不納入模擬規則」仍然有效，只有未來候選通過完整 `simUpdate` 後才可能改變。
- 建立本文件只代表計畫擬定；下載、工具開發、資料驗收、研究、App 正式化、commit 與 push 仍分段授權。

## 兩層資料的明確界線

| 層級 | 非正式大盤研究資料池 | 正式 App 大盤資料庫 |
|---|---|---|
| 使用者 | 開發、研究、候選與 Baseline 工具 | 實際使用者的 App |
| 儲存位置 | 本機 `exports/market-data/`，不進 Git | App 正式 SwiftData store |
| 建立時點 | 本計畫 `MKT-D01` | 有大盤規則正式採用後另案建立 |
| 資料取得 | 開發機受控回補及增量快取 | App 自己的下載、補齊及重算流程 |
| 是否有模擬狀態 | 沒有 | 市場資料本身仍沒有 Grade、買賣或加碼狀態 |
| 版本 | 獨立研究 dataset／`MTn` | 正式 schema、資料版本及遷移狀態 |
| 與 Baseline 關係 | 提供固定輸入快照 | 不反向作為正式 Baseline 的來源 |
| 一致性 | 自身可重建、可固定雜湊 | 與已核准研究 fixture／快照做重疊日期對照 |

正式化時可以重用已驗證的解析規格、公式與測試 fixture，但不能用「研究資料池已完成」代替 App 下載、schema、重算、遷移與實機驗證。

## 為什麼後續 Baseline 不必重新下載

非正式大盤採「來源月份快取＋不可變資料快照」：

1. 每個已完成月份保存原始回應、取得時間、來源型別與 SHA-256；驗收通過後不覆寫。
2. 當月尚未結束時，每次更新保存新 revision，不靜默改寫先前已被研究引用的內容。月份結束後另建立完成 revision。
3. 正規化資料依截止日、來源 revision、正規化器版本與市場技術值版本建立唯一 dataset ID。
4. Baseline 或候選只從既有快取建立所需日期分片，並在 manifest 固定 dataset ID、截止日及輸入雜湊；重播期間不連線。
5. 新 Baseline 的截止日在快取範圍內時是零下載重建；截止日往後延伸時，只補尚未擁有的當月／新月份。
6. 若 TWSE 後來修正歷史資料，建立新 revision 與新 dataset ID；舊 Baseline 仍指向原快照，不被回寫。

所以「可重複使用」不是永遠不再連線，而是已驗收歷史不重抓、只對新日期增量更新，且每次 Baseline 都能重現當時固定輸入。

資料池另將「原始資料」與「衍生技術值」分層：來源提供的欄位一次完整保存，日後真正新增公式時可以從原始快取離線建立新的 `MTn`，不需要重新下載或改動原始層。現行 `tUpdate` 已能類比的統計則在 `MT1` 一次算齊，不等研究想到用途後才逐欄擴充。

## 資料來源與 MT1 範圍

### 核心來源

- TWSE [發行量加權股價指數歷史資料](https://www.twse.com.tw/zh/indices/taiex/mi-5min-hist.html)（`MI_5MINS_HIST`）提供日期、開盤指數、最高指數、最低指數及收盤指數，頁面標示自 1999/01/05 起提供。
- TWSE [每日市場成交資訊](https://www.twse.com.tw/zh/trading/historical/fmtqik.html)（`FMTQIK`）提供同日市場成交股數、成交金額、成交筆數、發行量加權股價指數及漲跌點數。`MT1` 以「成交股數」作為大盤成交量；`FMTQIK` 的收盤指數同時用來核對 `MI_5MINS_HIST` 收盤值。
- [政府資料開放平臺資料集 11755](https://data.gov.tw/dataset/11755)列出 OHLC 五欄，[資料集 11672](https://data.gov.tw/dataset/11672)列出 `FMTQIK` 六欄；兩者皆標示每日更新、免費及政府資料開放授權條款第 1 版。日後增量優先使用明確開放資源；首次指定歷史月份回補仍視為 TWSE 網站歷史查詢，不把當日／最新月資料集的授權自動擴張到任意歷史端點。
- 歷史回補依 [TWSE 歷史資料下載標準](TWSE歷史資料下載標準.md)維持單線、保守間隔、有限退避、可停止與可續跑。精確參數不寫入公開計畫。

### 日期範圍

- 第一個正式研究快照截止於 Baseline v20 的輸入截止日 `2026/07/22`。
- 先取 `2016/01/01` 起的月份，再驗證最早 Baseline 決策日前至少已有 250 個大盤交易日；若不足，只向前增補到達標。
- 同一交易日只有一筆大盤資料，不因 A～E 共 50 檔股票而複製 50 次。

### 原始欄位完整保存

- 不以收盤指數填滿開盤、最高及最低；使用真實 OHLC。
- 納入 `FMTQIK` 市場成交股數，原始值以「股」保存，另除以 1,000 產生「張」作為市場技術計算輸入，對齊現行 `Trade.volumeClose` 的儲存單位。比例型 `v*` 不受股／張尺度影響，原始量、MA 與極值則必須明示單位。
- 成交量是整個集中市場的活動量，不是 TAIEX 各成分股成交量的精確加總替代品。依 TWSE 說明，其統計包含大盤、零股、盤後定價及鉅額交易，不含拍賣、標購；研究與正式 App 日後都必須沿用同一口徑。
- `FMTQIK` 可取得的成交股數、成交金額、成交筆數、發行量加權股價指數及漲跌點數全部進入原始快取與正規化資料；不因目前規則尚未使用就刪除欄位。
- 成交股數、成交金額、成交筆數都建立同一族市場活動技術值，避免未來為了新增量能、資金熱度或交易活躍度研究再改衍生資料架構。
- 若任一交易日缺少成交股數，該日成交量必須標為缺值而不是 0；缺值日不得推進市場 `v*` 統計。
- 本資料池的完整性是針對兩個已核准來源，不自動擴張到上櫃、電子、金融指數、期貨、匯率、新聞、基本面或總體資料；新增另一來源仍須另行確認用途、日期覆蓋與欄位語意。

## `MT1` 市場技術值

先依 [技術數值與研究原則](技術數值與研究原則.md)建立 `field-catalog.csv`，將現行欄位分成：

1. **價格型 `t*` 類比**：一次產生 OHLC 能支持的 MA20／MA60、MA 差與持續期、9 日高低、K／D／J、OSC／EMA／MACD、125／250 日高低位置，以及價格與各指標標準分數。
2. **必須改名或排除**：現行 `tHighDiff/tLowDiff` 含個股報價檔位及漲跌停封頂，不能原樣用於指數。若保留，須改成沒有個股封頂語意的指數盤中向上／向下幅度並使用新名稱。
3. **市場活動型類比**：成交股數、成交金額與成交筆數各自產生現行 `v*` 同族統計，包括原值、MA20／MA60、MA20／MA60 持續期、相對 MA 差、MA 差的 9 日極值與 125／250 日標準分數、原值 9 日極值及 125／250 日標準分數。
4. **不適用**：Grade、持股、資金、輪次、買賣及加碼欄位。這些不是市場歷史或市場技術值，不為了資料池寬度而製造無意義欄位。

市場活動三個系列使用同一個通用滾動統計器，欄位以 `marketVolume*`、`marketValue*`、`marketTransaction*` 分家，不把金額或筆數冒充成交量。每個市場欄位必須先寫明來源、公式、單位、暖機筆數、輸出精度與分類理由；不能因程式成功產生數字就視為語意成立。

### P0 凍結的欄位契約

原始層版本固定為 `market-daily-v1`。來源回應原檔不修改；正規化層使用 ISO `YYYY-MM-DD`、臺北時區，指數保留來源小數，成交股數、成交金額與成交筆數以 `Int64` 保存，`volume_lots` 才由原始股數除以 1,000 產生且不先取整數。

| 收盤位置 | `market_z_125`、`market_z_250` |
| KD | `market_kd_k`、`market_kd_k_max_9`、`market_kd_k_min_9`、`market_kd_k_z_125`、`market_kd_k_z_250`、`market_kd_d`、`market_kd_d_z_125`、`market_kd_d_z_250`、`market_kd_j`、`market_kd_j_z_125`、`market_kd_j_z_250` |

## 事前驗證規格

### A. 原始資料與正規化

1. 每個月份必須分別解析出 OHLC 五欄與 `FMTQIK` 六欄；錯誤頁、空回應、欄位改名或未完成請求不得標記成功。
2. 日期必須唯一且嚴格遞增；四價、成交股數、成交金額及成交筆數皆為非負有限值，四價另須為正；`high >= max(open, close)`、`low <= min(open, close)`、`high >= low`。
3. 與現行 TWSE 交易日曆及 A～E 個股行情做同日交叉核對。所有 Baseline 決策日都必須有大盤列；來源缺漏及日期對齊錯誤都必須為 0。
4. 兩來源以日期一對一合併；`FMTQIK` 的發行量加權股價指數與 `MI_5MINS_HIST` 收盤指數必須一致。缺少任一來源或收盤不一致都不得建立完整日列。
5. 事前固定 `2016-07`、`2020-03`、`2022-01`、`2024-08`、`2026-07` 五個月份，將每月首筆、中位筆、末筆共 15 筆 OHLC 與成交股數和另一種官方輸出格式或官方報表逐欄比對，必須全數一致。
6. 股轉張必須精確為 `volume_lots = volume_shares / 1000`；原始股數不得先四捨五入，張數允許小數。
7. 相同原始快取連續正規化兩次，`market-daily.csv`、品質統計與檔案雜湊必須一致；時間戳記不得混入決定性輸出。

### B. 市場技術值資格考

1. 價格先用五組凍結合成序列：水平、單調上升、單調下降、V 形反轉、單日高低尖峰；成交股數、成交金額與成交筆數各自使用固定值、單調增減、單日放大、單日縮小及合法零值序列。檢查公式方向、暖機、極值及分母為零處理，不得產生 NaN 或 Inf。
2. 以現行正式 Baseline A `browse.store` 的一檔完整 TWSE 歷史作唯讀正向控制，將其 OHLC 與 `volumeClose` 獨立送入 `MT1` 通用計算器；逐日對照同庫已由現行 `T2` 產生的 45 個可共用價格欄位與全部 18 個 `v*`。明確四捨五入欄位完全一致，其餘浮點容差不高於 `1e-9`，錯配為 0。這避免為資格考修改 App 或製造另一套 schema，同時直接檢驗目前正式 T2 全期結果。
3. 成交金額與成交筆數沒有現行 `Trade` 欄位作直接正向控制；同一個通用市場活動統計器必須先以成交股數重現全部現行 `v*`，通過後才用完全相同程式及參數套到金額與筆數。三系列的合成序列預期值仍須各自通過。
4. 正向控制只讀既有 Baseline，不修改其 store、App、集中股票資料池、Baseline 或報告；控制股票只用來證明公式一致，不能把其價格或成交量當成大盤研究資料。
5. 在至少 12 個事前固定截止日，以資料前綴獨立重算；每個截止日及以前的結果必須和完整歷史一致，證明沒有未來資料洩漏。
6. 分別保存價格及三個市場活動系列的實際 observation count；最早 Baseline 決策日前都必須已有 250 個過去大盤觀察，不把未成熟數值冒充完整 125／250 日指標。

### C. 快取與 Baseline 重用演練

1. 對同一已完整快取重跑更新器時不得發出網路請求，且原始列、技術列與雜湊零差異。
2. 分別建立截止 `2026/06/30` 與 `2026/07/22` 的快照；新快照在舊截止日以前的原始列及技術列必須和舊快照完全一致。

- **非正式資料池完成**：`P0～P3` 全部通過，manifest、`.complete`、兩次重建與 A～E 離線分片驗證一致。
- **市場研究就緒**：`R1` 完成，表示可用真實指數控制共同市場，不代表找到有效規則。
- **資料建立失敗**：來源不可靠、覆蓋不足、缺漏、公式錯配、未來洩漏或無法重建；不以策略分數是否改善定義。
- **後續沒有交易價值**：日後合格研究未發現大盤條件的額外貢獻。資料仍可用於窗口背景、市場相對控制與新樣本覆蓋檢查，不因沒有新規則就刪除。

## 正式 App 導入契約

只有市場候選通過完整回測並獲正式採用，才啟動獨立的 App 任務。該任務至少必須包含：

1. 依已採用規則實際需要選擇正式 App 欄位，再新增獨立 `MarketDay` SwiftData 模型；只有未來出現獨立保存技術序列的需求時才另拆 `MarketTechnical`。研究資料池不受這個較窄 schema 限制，也不把大盤偽裝成 `Stock/Trade`。
2. 首次建立或股群異動時，先從股群全部股票取得最早模擬起始日，再往前加入形成該日起有效市場技術值／價格路徑標籤所需的準備期；新增更早起始股票時必須向前補歷史並從受影響起點重建市場標籤，不能只沿用舊股群的較晚範圍。
3. App 自己的首次歷史補齊、失敗續跑、資料截止及來源切換流程。已完成月份與交易日須可重用，缺日不得填 0 或複製鄰日；市場資料是一日一筆，不隨股票數量重複。
4. 大盤日增量沿用個股價格更新的週期與觸發點，不建立另一套固定排程；但價格更新發生在盤中時，不查詢大盤日資料，也不把盤中指數、暫時成交量或未完成 OHLC 寫成正式市場日。收盤後的價格更新流程才取得來源已提供的最近完整市場日，補入後計算該日標籤，而該標籤最早從下一個交易日的盤中決策開始使用。
5. 盤中 `simUpdate` 依決策日嚴格查找較早的最後一個完整市場交易日；週末、休市、個股停牌或來源暫缺時都向前取最近完整日，不以日曆前一日、同日未收盤資料或臆造資料補位。若最新完整日落後，須保留可辨識的資料截止狀態，不默默宣稱市場狀態已更新。
6. 正式市場 schema／資料版本、技術版本、遷移與重算狀態；不能用研究 `MT1` 直接冒充正式版本。
7. App 正式資料與凍結 fixture／研究快照重疊日期的逐日 OHLC、適用技術值、價格路徑標籤及「前一完整市場交易日」對齊逐筆比較。
8. 市場資料不產生 Grade、買賣、加碼或資金狀態；`simUpdate` 只以唯讀的前一完整市場交易日 context 取用。
9. 市場規則造成行動變化時推進 `S`、完整重播正式 Baseline、驗證人工反轉與加碼、App 遷移、離線啟動、局部更新與實機資料建立。

研究資料池提供證據、公式規格及測試基準；正式 App 資料庫則由 App 建立、由正式版本管理。兩者的責任不得合併。
