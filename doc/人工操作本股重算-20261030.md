反轉買賣、手動加碼及取消操作只使用已保存行情，從操作日或更早未完成範圍重播本股必要計算。成功直接刷新結果；失敗、取消、依賴不足仍保留已保存人工意圖及待辦，不假裝完成，也不自動補抓資料。真正版本遷移與獨立價格更新沿用原流程。

## 原因與修正

`SimulationInputWriter` 正確保存意圖及 S dirty，但原 `downloadTrades → runRequest` 把 dirty 視為恢復要求，再由 UI callback 與 `unifiedUpdateScope` 擴成全股更新。日常管線只要人工操作摘要非空，也會使用「資料規則更新結果」彈窗。

改為兩種 UI／舊入口共用 `Technical.recalculateManualInput`，序列化本股本機重算，保留原 T／S 依賴與人工操作驗證。需要當日暫算前態時只讀既有交易日曆快照，不更新日曆；依賴不足不進入 P10 的恢復 callback。有效盤中 P10 仍保留十個假設價及原價還原。此入口不修改查價時間，不建立、取消或重設即時 timer；獨立排定的更新仍依原忙碌閘門接續。

歷史查核：`a50d49b` 前的 `9797f4ad792c22fa6453b2b62c768a5482a0e588`，兩個入口本來要求單股 `.simUpdateFrom`；非 realtime 分支使用既有資料重算 S。共用外殼原有日曆查詢及完成後即時 timer 副作用，不是人工操作的必要輸入。此次保留 `a50d49b` 引入的持久意圖／dirty 安全性，只隔離分流。

策略、T4/S65、市場7、S51／Baseline v41／DecisionBase v27不變；TWSE成功缺日續算、250日及歷史完整化、同輪來源結束後一次必要計算契約不變。
