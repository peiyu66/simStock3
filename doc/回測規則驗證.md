# 回測規則驗證

本文件記錄 simStock3 的 Grade、買進、賣出、加碼與固定成交假設，以及驗證方法、正式規則代號、實驗結果與採用決策。目的不是證明某條規則永遠有效，而是讓每次修改都能回答：

1. 改了哪一條規則，以及原本想解決什麼問題。
2. 使用哪一份資料、股票群、期間與比較基準（Baseline）。
3. 追高（H）、承低（L）與合計分數如何變化，是否跨期間一致。
4. 為什麼採用、拒絕、保留或等待不同樣本重驗。

詳細逐股數據仍保存在本機 `exports/backtest-reports/<run-id>/`。該目錄是產生物，不納入 Git；本文件保存可長期追蹤的結論與 run ID。

## 名詞與縮寫

- **H（High，追高）**：股價與技術指標呈現相對強勢時，評估是否順勢買進的規則與測試股群。
- **L（Low，承低）**：股價與技術指標進入相對低檔時，評估是否承接買進的規則與測試股群。程式先判斷 H，未成立 H 時才判斷 L。
- **MA20／MA60（20／60 日移動平均線）**：用來描述中短期平均價格、方向及現價相對均線的位置。
- **K／D／J（隨機指標）**：K 是較快的價格位置指標，D 是較慢的平滑基準，J 放大 K 相對 D 的偏離。
- **OSC（MACD 動能差值）**：用來描述短期與長期價格動能的差異。
- **標準分數（程式欄位以 Z 表示）**：用來描述目前價格、技術指標或成交量相對自身近期常態的位置；欄位的完整解讀與研究原則見[技術數值與研究原則](技術數值與研究原則.md)。
- **Grade（動態評等／[選股評等](選股評等.md)）**：依該股票先前模擬結果的[實年報酬率](報酬率.md#實年報酬率)與[平均持股週期](週期.md)，分為 `wow（+3，紅星）`、`high（+2）`、`fine（+1）`、`none（0）`、`weak（-1）`、`low（-2）`、`damn（-3）`，用來調整部分買賣門檻。
- **Baseline（比較基準）**：已確認保留的正式規則及其回測結果。每個候選只和使用相同股票、資料、期間及模擬設定的 Baseline 比較。
- **ROI（[實年報酬率](報酬率.md#實年報酬率)）**：本文件用來評估規則報酬表現的年化數值。
- **days（平均持股週期）**：完成一輪買進至賣出平均需要的天數。

## 代號規則

程式規則代號不依實驗先後重編，以免日後插入新測試造成全面改號：

- `G-Pnn`、`G-Nnn`、`G-Tnn`、`G-Mnn`：Grade 的正向分類、負向分類、啟用門檻與門檻映射。
- `H-Pnn`：H 的 Positive（加分）條件，例如 `H-P04` 是追高成交量加分。
- `H-Nnn`：H 的 Negative（扣分）條件。
- `H-Cnn`：H 的 Calendar（季節）條件。
- `H-Tnn`：H 的 Threshold（成立門檻）。
- `L-Pnn`、`L-Nnn`、`L-Cnn`、`L-Tnn`：L 使用相同的加分、扣分、季節與門檻分類。
- `S-Pnn`、`S-Nnn`、`S-Tnn`：賣出加分、惜賣扣分與實際退出門檻。
- `A-Pnn`、`A-Nnn`、`A-Tnn`、`A-Enn`：加碼加減分、候選資格與實際執行限制。
- `E-nn`：不屬於單一技術訊號、但會改變成交結果的固定成交與資金假設。
- `H-Rnn`、`L-Rnn`、`S-Rnn` 等：Retired，已退出正式程式、但保留驗證歷史的規則。
- `H1`、`H2a`、`L6b`、`S2c`、`A5d` 等：一次實驗的代號，不是程式規則代號。

新增正式規則時，在相同分類中使用下一個未用編號；不得因刪除規則而重編既有代號。若一行包含可獨立拆解的兩個子條件，使用 `a`、`b` 後綴，例如 `H-P03a/b`。

## 評估方式

### 分數

每個股票、每個模擬期間以實年報酬率（ROI）與平均持股週期（days）計分：

- ROI ≥ 0：`score = ROI × 100 ÷ days`
- ROI < 0：`score = ROI × days ÷ 100`
- 沒有成交：不計分。
- 0、Inf、NaN：視為資料或程式錯誤，停止回測，不接受報告。

H 與 L 股群分別彙總，再相加成為主分數。分數用來比較同一資料與同一窗口制度下的新舊規則，不代表未來報酬。

### 不只看合計分數

「分析摘要」至少同時檢查：

- H、L 是否一邊改善、另一邊明顯退步。
- 各窗口是否方向一致，或只靠單一期大幅上升。
- ROI 改善是否伴隨持股週期惡化。
- 規則是否只在極少數、互相抵銷或難以解釋的條件中生效。
- 修改是否只是經由動態 Grade 改變後續 H／L 分流，而非直接改善目標股群。
- 加碼候選是否只是投入更多本金換取較高分；應優先尋找在分數、ROI 與持股週期不惡化下，能減少超次加碼或資金占用的規則。

不設自動採納門檻。每次報告後共同判讀，必要時拆條件、改參數或重測。

### 狀態

- **採用**：候選規則已成為新 Baseline。
- **拒絕**：候選有清楚且不可接受的負面結果。
- **保留原規則**：候選未證明比目前規則好。
- **待不同樣本重驗**：影響太小、方向不一致或樣本不足，不能視為永久定論。
- **未檢驗**：已有正式代號，但尚未做獨立拆解測試。

「保留原規則」與「待不同樣本重驗」可以同時成立。例如 H5a 沒有改善，故不採用；但變化極小，換股票群或窗口後仍值得再驗證。

### 規則檢驗進度

現行規則登錄表使用以下覆蓋狀態，狀態描述的是「這條正式規則被檢驗到什麼程度」，不等同採用決策：

- **未檢驗**：尚未以候選規則改動它。
- **整組檢驗**：曾和同組規則一起移除或改寫，尚不能單獨歸因。
- **部分拆解**：已測過部分分支、門檻或組合，仍有未獨立確認的內部條件。
- **已獨立檢驗**：曾把該規則作為主要變因；結論仍只適用於當時 Baseline 與樣本。

正式代號對應目前程式中的一個可獨立開關或調整門檻的判斷。條件內只是共同構成同一現象的比較式可以共用代號；若分支可分開保留、移除或調參，使用 `a／b` 後綴。規則退出後保留原代號並移入 `R` 表，不把後續規則重新編號。

### 適合重新驗證的時機

- H、L 股票名單更換。
- 歷史資料增加到能形成新的完整三年窗口。
- 修正歷史交易、技術指標或模擬錯誤並重建快照。
- Grade、賣出、加碼或其他上游規則有實質變動。

一般 UI 修改或單純更新 App 版本不需重驗。
