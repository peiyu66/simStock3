## 假設與唯一變因

暫定候選代號 **A-EARLY15-ROI20-BOTTOM-P1**，建議精確讀法如下：

| 項目 | 候選定義 |
| --- | --- |
| 評估時機 | 已有庫存、當日未由正式 S 規則賣出，進入 A 加碼評估時 |
| 15天內 | 當輪持股 `1 <= simDays <= 15`；沿用 App 的日曆日，首次買入日為第1天，週末／休市日亦累計。不是15個交易日，也不是距上次加碼15天 |
| ROI | 當日決策時、加碼前的 `simUnitRoi = 100 × (當日成交價 − 原持股單位成本) ÷ 原持股單位成本`；嚴格 `< -20`，等於−20%不算。不是當日股價跌幅、最低價跌幅或累積實年報酬率 |
| 探底前／後期 | 決策當日個股[價格路徑](價格路徑狀態持久化計畫.md)為 raw 6 或7，兩階段任一成立；不用 Grade 趨勢或大盤階段代替 |
| 分數 | 條件全部成立時，A 總分獨立 **+1**，每次評估最多一分；不因前／後期重複計分 |
| 其他條件 | 沿用全部正式票數、共享上限、A-T01／A-T02、S優先、加碼冷卻、次數與資金限制；不限 Grade，不另加大盤、7.5%跌幅、首次加碼或前案排除wow條件 |

「+1」與日曆日／ROI定義為本次設計建議，後續若使用者另有意思，先更新規格再盤點。研究從正式 S44 開始，不疊加上個未採用的扣票候選。機制只影響 A，不能同時減 S 分數來保護新加碼，也不修改後續38日冷卻以消除不利案例。

## 先辨識分數與加碼資格的差別

[現行 A-T01](現行回測規則.md)在這15天內仍要求 **ROI < −25% 且 A至少3分**；更深的分級虧損分支不會放寬這個範圍。A-T02要求ROI介於−10%與1%，與本假設不重疊。

因此本版雖在 ROI < −20% 時加分，**−25% <= ROI < −20% 的加分會被原虧損資格吸收**；等於−25%也不能經A-T01加碼。真正直接增加成交的典型邊界是持股15天內、探底6／7、ROI < −25%、原A2分→3分，且執行／資金條件都通過。原A不足2分者可能仍不通過，原A至少3分且已成交者可能只有票數改變。

這表示純加分版只能回答「在原本已夠深跌的早期探底，加一票是否改善效率」，**不能回答「跌20%就能提早加碼是否有效」**。若使用者希望後者，應另提只調整早期虧損資格的單一變因設計；不在本版暗中把−25%改成−20%，也不把資格阻擋的零行動差異解讀為原早期加碼假說無效。

### 判讀順序

- **主要成效：** 每個樣本及股群／固定窗口的既有[效率分數與實年報酬率](報酬率.md)，並列[平均持股週期](週期.md)、輪次及期末持倉；不用自創ROI／週期權重。報告改善／退步／不變股窗、幅度與集中度。
- **目標機制：** 逐一追首次分歧所在輪次，列加碼是否提早、成本／張數、退出日期、持股天數、損益與後續輪次。週期縮短但效率下降，屬目標只達一半；效率改善但週期沒有縮短，可保留收益證據，但不能宣稱已證實縮短週期機制。
- **資金與反證：** 最高投入成本、最低現金、第二加碼時點、38日冷卻連鎖、投入份數、資金不足／超額旗標、超過180／360日與未平倉長輪。提早投入後輪次變短，不一定代表資金占用降低，須並列投入金額與占用日數。
- **分歧解釋：** 原票與新票各自作用、加碼後ROI／Grade／庫存及賣出資格連鎖分開說明。不把單日便宜、單輪賺更多或一個樣本正向當作完整成功，也不要求所有樣本零反向。

若起始結果值得續驗，再提出同一凍結候選的C／D各一次／60股窗與明確預期取捨；不重用上次扣票候選的分數。E／九年壓力與正式採用分別授權，九年只作路徑風險脈絡，固定三年為主要採納證據。採用前仍須依正式Baseline流程完整處理全部樣本。
