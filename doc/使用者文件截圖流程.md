# 使用者文件截圖流程

## 用途

本流程建立可重複的 13 吋 iPad 使用者文件環境，用來更新 README 與 Grade 相關介面截圖。展示資料與正式使用者資料、固定回測 Baseline 及 A／B／C／D 樣本分離；展示股票不是選股推薦，也不作為規則證據。

## 固定環境

- 裝置：全新的 `iPad Pro 13-inch (M5)` Simulator，名稱使用 `simStock3 iPad 13-inch Docs`。
- App：當次工作目錄建置的最新 Debug App。
- 資料來源：集中資料池 `central-pool-2016-07-22-working-v1/pool.store`。
- 股群名稱：沿用 App 預設的 `股群_1`，不要使用「文件展示」等專用名稱，以便與一般使用者畫面直接對照。
- 展示股群：`2449 京元電子`、`3231 緯創`、`1101 台泥`、`2882 國泰金`、`2634 漢翔`、`9910 豐泰`、`2317 鴻海`、`1477 聚陽`。
- 資料截止：種子沿用資料池固定截止日，不重新下載完整歷史行情。一般方式啟動 App 後，正式啟動流程可能自動增量補齊截止日之後的近期月份；應等待八檔全部完成再截圖，不另外手動重抓九年資料。

## 資料原則

1. 使用 Debug 啟動參數 `--prepare-documentation-screenshot-store`，從集中資料池建立 `Documents/DocumentationScreenshotSeed/default.store`。
2. 種子只複製歷史行情與現行 `T` 技術欄位，不沿用資料池的模擬結果、Grade、趨勢或人工操作。
3. 停止 App 後，以種子覆蓋新 Simulator 的 `Library/Application Support/default.store`，再用一般啟動方式開啟 App。`Documents` 只保存種子與內部資料池，不是正式 SwiftData 儲存位置。
4. 由 App 從最早受影響日重播現行 `S`；完成後才截圖。這次固定資料為 `T2/S21`。
5. 不從既有使用者 App 複製資料，避免把私人股群、人工反轉、手動加碼或暫時畫面狀態帶入文件。

## S22 schema 注意事項

- `S22` 起 `Trade` 增加 `simFitTrendPhaseRaw`。既有截圖種子及展示 store 不因安裝新版 App 就自動視為有效 S22；每次重做文件環境都應由行情與 T 種子重新建立正式 store，再完整重播當時最新 S。
- 種子必須覆蓋 `Library/Application Support/default.store`；放在 `Documents` 只會成為未被 App 使用的副本。App 能啟動或畫面能顯示股票，都不能取代實際 store 路徑、schema 欄位及八檔 Stock 版本核對。
- 這次既有四張截圖仍記錄 `T2/S21` 當時畫面，不因程式升到 S22 而回頭改稱 S22。下次需要更新截圖時，才以新建 S22 或更高版本展示庫重做。

## 標準截圖

1. `ipad-portrait-list.png`：直式股票清單，呈現八檔展示股及 Grade／趨勢位置。
2. `ipad-portrait-page.png`：直式個股交易，呈現 Trade List 每日 Grade／趨勢。
3. `ipad-landscape-page.png`：橫式一般交易畫面，呈現側欄與未受技術欄壓縮的完整 Trade List。
4. `ipad-landscape-technical.png`：橫式三欄技術檢視，呈現側欄、Trade List、技術檢視，以及累計損益旁的平均週期。

圖片存入 `doc/screenshots/YYYYMMDD/`，README 同步改指向新目錄。截圖時保持狀態列乾淨、避免警告與載入畫面，選擇能清楚呈現 Grade 及趨勢的股票與交易日；可以為說明介面切換顯示股票，但不得改造模擬數值或把展示結果解讀成策略驗證。

## 完成條件

- 新 Simulator 只有八檔展示股票，且全部由現行 `S` 完整重播。
- 四張截圖沒有截斷、溢出、載入遮罩或起始本金不足警告。
- Grade、趨勢色彩、Trade List 圖示、累計損益與平均週期符合當前 App。
- README 與 Grade 使用者文件的文字、色彩及圖片一致。
- 完成後保持文件用 13 吋 Simulator 開機並停留在橫式技術檢視，方便直接確認。
