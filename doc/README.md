## 正式規則與驗證歷史

- [工作交接](工作交接.md)：只保留最新進度、工作樹狀態、授權邊界及待討論問題；新交談先讀，但不取代正式規則與 manifest。
- [工作交接歷史](工作交接歷史/README.md)：依時間保存每次交接快照，作為可回顧的工作日誌。
- [現行回測規則](現行回測規則.md)：目前正式 Baseline、股票樣本及 Grade／買進／賣出／加碼條件的權威清單。
- [回測規則驗證](回測規則驗證.md)：實驗方法、候選結果、採用／拒絕理由及重驗結案歷史；頂端保存有日期的目前狀態導覽。
- [Baseline 歷史](Baseline歷史.md)：歷次真正成為後續比較基準的正式 Baseline 索引。

## 文件維護原則

- 現行精確條件只在[現行回測規則](現行回測規則.md)維護；研究計畫與歷史結論不取代它。
- 候選只有正式採用後才進入現行規則；未採用結果保留在驗證歷史與本機 `exports`。
- `exports` 是可重建或大型產生物，通常不納入 Git；長期有效的判讀寫回文件。
- 舊導入計畫可保留設計脈絡，但開頭應指向接續管理的現行文件，避免舊門檻被當成目前規則。
